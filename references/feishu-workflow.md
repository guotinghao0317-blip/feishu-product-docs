# 飞书取材与交付操作

## 定位和确认

- 首次使用按 [安装、授权和建群](../README.md) 完成接入。使用用户指定的群，或读取 `feishu-product-docs.local.json` 的 `chat` 与 `assistants`。群内历史问题发给 `research`，跑数问题发给 `bi`。
- 可用 `lark-cli im +chat-search --as user --query "<群名>"` 查群 ID。首次向该群提问或群配置变更时，用 `lark-cli im chats get --as user --chat-id "<群ID>"` 和 `lark-cli im +chat-members-list --as user --chat-id "<群ID>" --member-id-type open_id --page-all` 核对群名、成员名称与 ID。名单受服务端上限截断或出现重名时，请有权限的人确认接收对象，再发消息。
- 群内提问显式使用 `--as user`。验证助理是否真正回复，用发送结果中的真实提及和群内回复确认。认证失败时核对 CLI 用户身份和 OAuth。运行环境无法访问系统钥匙串时，从能使用系统钥匙串的交互环境完成授权或检查。继续使用 CLI 的凭证存储。

## 向资料助手取历史

提问包含主题、时间范围、要回答的问题，以及所需交付物：

> 请检索【主题/时间范围】，重点核对【问题和容易混淆的状态】。请把完整检索结果整理为我有权限读取的飞书云文档，并把文档链接发回群里；同时列出相关会议纪要、需求/PRD、调研/评审和关键原始消息的链接（有消息 ID 一并给出），简要标明每项涉及什么结论。请区分已确认、提议和待核实。若生成 Aily 任务，请另附任务链接，并在云文档中保留全文、表格和引用链接。

用 `lark-cli im +messages-send --as user --chat-id <群ID> --text @<问题文件>`。问题文件开头写 `<at user_id="ou_…">显示名</at>`，把占位符换成当前 CLI 应用从群成员列表取到的助手 open_id 和名称。首次可加 `--dry-run` 预览。发送后看结果的 `mentions` 和飞书界面，确认提及已被识别。每条查询保存返回的消息 ID 和发送时间；重试同一次发送可复用 `--idempotency-key`，避免重复触发。

用 `lark-cli im +chat-messages-list --as user --chat-id "<群ID>" --start "<发送时间，ISO 8601>"` 查看群消息。若回复在话题里，用 `lark-cli im +threads-messages-list --as user --thread "<消息ID或话题ID>"`。核对回复者和任务关联，收件确认或处理中只是进度，拿到可读的完整结果才算取回。等待时继续处理其他已知资料，按有界间隔查看；无回应先复核身份、@ 和线程，必要时只做一次有明确原因的追问。用户可在飞书客户端手动 @，随后交给你全文和原始链接。

用 `lark-cli docs +fetch --as user --doc <链接> --doc-format markdown` 读完整云文档，再读关键原始链接；已知消息 ID 时用 `lark-cli im +messages-mget --as user --message-ids <消息ID>` 回读并取可用的消息链接。CLI 的 OAuth 与 Aily 网页登录独立。只有 Aily 任务链接或群内摘要时，先请求将完整任务导出为飞书云文档，保留任务链接；分别记录完整导出、Aily 原任务页和关键引用原文的实际读取状态。

## 向BI 助手取数

历史材料读完且本次任务需要取数时，沿用同一群与用户身份，单独 @ BI 助手。先写清数据要解决哪个决策，再把它翻成可执行的口径：

> 为判断【决策】，请按【日期/时区、产品、车型/版本、人群与排除项】查询【指标及分子/分母、去重规则】。需要【对比期、分组、粒度与输出表字段】。请返回汇总和必要明细、口径、数据更新时间、缺失分区或不可获取项；有结果文档、查询链接或附件请一并给出。

PRD 例如先从历史流程找出「场景出现 → 功能曝光 → 发起 → 成功」的待验证环节，再决定要查触达规模、转化还是失败原因；不要默认每个环节都已埋点。口径未知的地方请 BI 说明实际可用定义。核对实际回复与查询，差异会改变结论时先厘清，再写结果。

## 飞书写入

- 语法以安装版本的 `--help` 和 `lark-cli skills read lark-doc` 为准。新建时按当前创建流程检查草稿，用 DocxXML 生成高亮块与表格。标题按用户约定手写一级中文编号和二级数字编号，省略自动编号属性。
  ```xml
  <title>文档标题</title>
  <callout emoji="💡"><p><b>核心判断</b></p><ul><li>关键差异或下一步</li></ul></callout>
  <h1>一、数据覆盖</h1>
  <p>按相同对象和统计口径比较。</p>
  <h1>二、交互流程</h1>
  <h2>2.1 主流程</h2>
  <p>写清触发和执行路径。</p>
  <h2>2.2 异常处理</h2>
  <p>写清边界条件及反馈。</p>
  ```
- 文本用 `@文件` 传给 CLI。新建用 `docs +create --as user`；修改先 `docs +fetch --as user --detail with-ids` 找到当前范围，再用 `docs +update --as user` 定点修改并保留其他内容。用 `docs +fetch --as user --doc <交付链接>` 回读验证实际块结构与文字；局部问题在原文档修复，避免重复新建。
